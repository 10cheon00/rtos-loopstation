# 상태 오류 판별 정보 생성

## 1. 기능 범위

| 항목 | 내용 |
| --- | --- |
| 기능 ID | `FEAT-STATE-021` |
| 상위 설계 문서 | `ARCH-STATE.md` |
| 관련 설계 항목 | `ARCH-STATE-021` |
| 관련 요구사항 | `REQ-STATE-006` |
| 주요 목적 | 상위 오류 정책이 실패 위치와 원인을 판단하도록 정형화된 상태 오류 정보를 생성한다. |
| 제외 범위 | 오류 심각도에 따른 시스템 ERROR 전이와 사용자 표시 |

## 2. 연결된 상위 설계 항목

| 설계 항목 ID | 설계 항목 | 연결 내용 |
| --- | --- | --- |
| `ARCH-STATE-021` | 오류 판별 정보 | 상위 오류 정책이 실패 위치와 원인을 판단하도록 정형화된 상태 오류 정보를 생성한다. |

## 3. 목적

상위 오류 정책이 실패 위치와 원인을 판단하도록 정형화된 상태 오류 정보를 생성한다.

## 4. 입력

| 입력 | 설명 |
| --- | --- |
| StateEvent | 오류를 유발한 이벤트 |
| 대상 정보 | machine ID와 instance ID |
| 현재 상태 | 오류 시점 state ID |
| 오류 원인 | 실패 단계와 code |

## 5. 출력

| 출력 | 설명 |
| --- | --- |
| StateErrorInfo | 이벤트, 대상, 상태, 단계와 원인 |
| 오류 전달 결과 | 진단 sink 전달 여부 |

## 6. 구현 기준

| 항목 | 기준 |
| --- | --- |
| 필수 정보 | event, machine, instance, state ID를 포함한다. |
| 단계 구분 | validation부터 on_enter까지 구분한다. |
| 원본 포인터 금지 | 수명이 짧은 payload 포인터를 저장하지 않는다. |
| bounded 처리 | 상태 태스크에서 제한 시간 안에 생성한다. |

## 7. 완료 기준

| 기준 | 확인 방법 |
| --- | --- |
| 필드 보존 | 대표 오류의 식별자를 확인한다. |
| 단계 판별 | 서로 다른 실패 단계가 구분되는지 확인한다. |
| 수명 안전성 | 원본 이벤트 재사용 후에도 정보가 유효한지 확인한다. |

## 8. 구현 및 검증 상태

| 항목 | 상태 | 날짜 | 비고 |
| --- | --- | --- | --- |
| 구현 | 미구현 | - | 기능 명세에 따른 구현이 필요하다. |
| 검증 | 미검증 | - | 구현 완료 후 완료 기준에 따라 검증한다. |

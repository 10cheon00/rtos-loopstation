# 외부 상태 자원 조립

## 1. 기능 범위

| 항목 | 내용 |
| --- | --- |
| 기능 ID | `FEAT-STATE-022` |
| 상위 설계 문서 | `ARCH-STATE.md` |
| 관련 설계 항목 | `ARCH-STATE-022` |
| 관련 요구사항 | `REQ-STATE-002` |
| 주요 목적 | 상태 머신에 필요한 RTOS 및 command 자원을 태스크 생성 전에 외부에서 준비한다. |
| 제외 범위 | 개별 자원의 CubeMX 설정과 상태 머신 내부 사용 방법 |

## 2. 연결된 상위 설계 항목

| 설계 항목 ID | 설계 항목 | 연결 내용 |
| --- | --- | --- |
| `ARCH-STATE-022` | 외부 자원 조립 | `main.c`와 같은 외부 조립 지점이 자원을 생성하고 초기화 인자에 설정한다. |

## 3. 목적

상태 관리 태스크가 자원 생성과 구체 하드웨어 및 RTOS 설정 책임을 갖지 않도록, 필요한 자원을 태스크 외부에서 미리 조립한다.

## 4. 입력

| 입력 | 설명 |
| --- | --- |
| CubeMX 생성 자원 | queue, semaphore 등의 RTOS handle |
| command 전달 경로 | 상태 머신이 요청을 전달할 queue 또는 port |
| 상태 머신별 의존성 정의 | 각 머신이 필요로 하는 자원 목록 |

## 5. 출력

| 출력 | 설명 |
| --- | --- |
| 구성된 자원 참조 | 초기화 인자에 저장할 유효한 handle 및 port |
| 조립 결과 | 필수 자원 누락 없이 태스크를 생성할 수 있는 상태 |

## 6. 구현 기준

| 항목 | 기준 |
| --- | --- |
| 조립 시점 | 모든 필수 자원을 상태 관리 태스크 생성 전에 준비한다. |
| 생성 위치 | 자원 생성과 handle 설정은 `main.c`의 CubeMX USER CODE 영역 등 외부 조립 지점에서 수행한다. |
| 태스크 내부 생성 금지 | 상태 관리 태스크와 상태 머신 초기화 함수는 RTOS 자원을 생성하지 않는다. |
| 오류 처리 | 필수 자원이 생성되지 않았으면 상태 관리 태스크를 정상 실행 상태로 진입시키지 않는다. |

## 7. 완료 기준

| 기준 | 확인 방법 |
| --- | --- |
| 생성 위치 | 상태 태스크 내부에 RTOS 자원 생성 코드가 없는지 확인한다. |
| 생성 순서 | 자원 생성과 인자 설정 후 태스크가 생성되는지 확인한다. |
| 누락 차단 | 필수 자원 누락 시 이벤트 처리가 시작되지 않는지 확인한다. |

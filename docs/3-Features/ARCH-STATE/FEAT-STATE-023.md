# 상태 초기화 인자 구조 정의

## 1. 기능 범위

| 항목 | 내용 |
| --- | --- |
| 기능 ID | `FEAT-STATE-023` |
| 상위 설계 문서 | `ARCH-STATE.md` |
| 관련 설계 항목 | `ARCH-STATE-023` |
| 관련 요구사항 | `REQ-STATE-002` |
| 주요 목적 | 태스크 자체와 각 상태 머신의 의존성을 정형화된 초기화 인자로 구분한다. |
| 제외 범위 | 자원 생성과 개별 상태 머신의 도메인 데이터 구조 |

## 2. 연결된 상위 설계 항목

| 설계 항목 ID | 설계 항목 | 연결 내용 |
| --- | --- | --- |
| `ARCH-STATE-023` | 정형화된 초기화 인자 | `StateInitParams`가 태스크 의존성과 머신별 전용 인자를 구분해 제공한다. |

## 3. 목적

태스크가 불투명한 전역 자원을 참조하지 않고, 사용 가능한 의존성을 타입으로 명시하도록 `StateInitParams`와 상태 머신별 InitParams를 정의한다.

## 4. 입력

| 입력 | 설명 |
| --- | --- |
| 태스크 의존성 목록 | `state_event_queue` 등 상태 관리 태스크가 직접 사용할 자원 |
| 시스템 머신 의존성 | 시스템 상태 머신만 사용할 자원 |
| 트랙 머신 의존성 | 트랙 상태 머신만 사용할 자원 |
| 디스플레이 머신 의존성 | 디스플레이 상태 머신만 사용할 자원 |

## 5. 출력

| 출력 | 설명 |
| --- | --- |
| `StateInitParams` | 태스크 의존성과 머신별 InitParams를 포함한 상위 구조체 |
| 상태 머신별 InitParams | 해당 머신에 필요한 자원만 포함하는 전용 구조체 |

## 6. 구현 기준

| 항목 | 기준 |
| --- | --- |
| 계층 분리 | `StateInitParams`에 태스크 의존성과 머신별 InitParams를 별도 필드로 둔다. |
| 최소 의존성 | 각 머신별 InitParams는 해당 머신이 사용하지 않는 자원을 포함하지 않는다. |
| 타입 공개 | 초기화 함수와 외부 조립 지점이 공유할 수 있는 헤더에 구조체 타입을 정의한다. |
| 임의 타입 차단 | 조립 지점이 필드 순서나 크기를 임의로 해석하지 않도록 동일한 타입 정의를 사용한다. |

## 7. 완료 기준

| 기준 | 확인 방법 |
| --- | --- |
| 필드 분리 | 태스크 자체 자원과 각 머신 자원이 구분되는지 확인한다. |
| 의존성 격리 | 한 머신의 InitParams로 다른 머신 전용 자원에 접근할 수 없는지 확인한다. |
| 타입 일치 | `main.c`와 초기화 함수가 동일한 헤더 타입을 사용해 빌드되는지 확인한다. |

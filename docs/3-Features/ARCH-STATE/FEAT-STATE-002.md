# 상태 머신 인스턴스

## 1. 기능 범위

| 항목 | 내용 |
| --- | --- |
| 기능 ID | `FEAT-STATE-002` |
| 상위 설계 문서 | `ARCH-STATE.md` |
| 관련 설계 항목 | `ARCH-STATE-002` |
| 관련 요구사항 | `REQ-STATE-001` |
| 주요 목적 | 현재 상태, 전용 context, 식별 정보와 허용 상태 집합을 독립된 인스턴스로 구성한다. |
| 제외 범위 | 도메인별 context 멤버와 상태 구현 내부 데이터 |

## 2. 연결된 상위 설계 항목

| 설계 항목 ID | 설계 항목 | 연결 내용 |
| --- | --- | --- |
| `ARCH-STATE-002` | 상태 머신 인스턴스 | 현재 상태, 전용 context, 식별 정보와 허용 상태 집합을 독립된 인스턴스로 구성한다. |

## 3. 목적

현재 상태, 전용 context, 식별 정보와 허용 상태 집합을 독립된 인스턴스로 구성한다.

## 4. 입력

| 입력 | 설명 |
| --- | --- |
| 상태 머신 식별 정보 | machine ID와 instance ID |
| 초기 상태 참조 | 인스턴스의 시작 상태 |
| context 참조 | 상태들이 공유할 도메인 데이터 |
| 허용 상태 집합 | 해당 머신에 속한 상태 목록 |

## 5. 출력

| 출력 | 설명 |
| --- | --- |
| 상태 머신 인스턴스 | 공통 실행 단위 |
| 현재 상태 조회값 | 이벤트 처리에 사용할 상태 참조 |

## 6. 구현 기준

| 항목 | 기준 |
| --- | --- |
| 필드 분리 | 현재 상태와 context 및 식별자를 명시적으로 구분한다. |
| 인스턴스 독립성 | 한 인스턴스의 변경이 다른 인스턴스에 영향을 주지 않아야 한다. |
| 필수 참조 | 실행 가능한 인스턴스는 초기 상태와 context가 유효해야 한다. |
| 캡슐화 | 외부에서 현재 상태 필드를 직접 수정할 수 없어야 한다. |

## 7. 완료 기준

| 기준 | 확인 방법 |
| --- | --- |
| 초기 구성 | 등록 정보가 모든 필드에 보존되는지 확인한다. |
| 독립성 | 두 인스턴스의 context가 섞이지 않는지 확인한다. |
| 잘못된 구성 | 필수 참조 누락 시 초기화가 실패하는지 확인한다. |

# canonical state 단일 변경 주체

## 1. 기능 범위

| 항목 | 내용 |
| --- | --- |
| 기능 ID | `FEAT-STATE-003` |
| 상위 설계 문서 | `ARCH-STATE.md` |
| 관련 설계 항목 | `ARCH-STATE-003` |
| 관련 요구사항 | `REQ-STATE-001` |
| 주요 목적 | canonical state의 쓰기 경로를 상태 관리 태스크 내부 API로 제한한다. |
| 제외 범위 | 다른 태스크의 이벤트 생성과 읽기 전용 상태 조회 |

## 2. 연결된 상위 설계 항목

| 설계 항목 ID | 설계 항목 | 연결 내용 |
| --- | --- | --- |
| `ARCH-STATE-003` | 단일 변경 주체 | canonical state의 쓰기 경로를 상태 관리 태스크 내부 API로 제한한다. |

## 3. 목적

canonical state의 쓰기 경로를 상태 관리 태스크 내부 API로 제한한다.

## 4. 입력

| 입력 | 설명 |
| --- | --- |
| 상태 머신 인스턴스 | 상태 변경 대상 |
| 검증된 다음 상태 | 공통 전이 절차가 확정한 목적 상태 |

## 5. 출력

| 출력 | 설명 |
| --- | --- |
| 갱신된 현재 상태 | commit된 canonical state |
| 변경 거부 결과 | 잘못된 호출 또는 참조 오류 |

## 6. 구현 기준

| 항목 | 기준 |
| --- | --- |
| 비공개 변경 | current state 쓰기 API는 상태 관리 모듈 내부에 둔다. |
| 단일 writer | 다른 태스크는 StateEvent만 전송해야 한다. |
| 읽기 일관성 | 외부에는 읽기 전용 조회나 snapshot만 제공한다. |
| 검증 선행 | 전이 검증 후에만 쓰기를 수행한다. |

## 7. 완료 기준

| 기준 | 확인 방법 |
| --- | --- |
| 우회 쓰기 차단 | 공개 헤더로 current state를 직접 바꿀 수 없는지 확인한다. |
| 이벤트 경로 | 외부 변경 요청이 state_event_queue를 거치는지 확인한다. |
| 단일 commit | 한 전이에서 current state가 한 번만 변경되는지 확인한다. |

# 상태 이벤트 처리 완료 확인

## 1. 기능 범위

| 항목 | 내용 |
| --- | --- |
| 기능 ID | `FEAT-STATE-017` |
| 상위 설계 문서 | `ARCH-STATE.md` |
| 관련 설계 항목 | `ARCH-STATE-017` |
| 관련 요구사항 | `REQ-STATE-005` |
| 주요 목적 | 생명주기와 결과 확인이 끝난 뒤 현재 이벤트를 완료하고 다음 dequeue를 허용한다. |
| 제외 범위 | command 실행 완료 대기와 queue 생산자 통지 |

## 2. 연결된 상위 설계 항목

| 설계 항목 ID | 설계 항목 | 연결 내용 |
| --- | --- | --- |
| `ARCH-STATE-017` | 처리 완료 확인 | 생명주기와 결과 확인이 끝난 뒤 현재 이벤트를 완료하고 다음 dequeue를 허용한다. |

## 3. 목적

생명주기와 결과 확인이 끝난 뒤 현재 이벤트를 완료하고 다음 dequeue를 허용한다.

## 4. 입력

| 입력 | 설명 |
| --- | --- |
| 상태 처리 결과 | on_message 또는 전이 결과 |
| 생명주기 결과 | on_exit과 on_enter 결과 |
| 진단 결과 | 오류 기록 상태 |

## 5. 출력

| 출력 | 설명 |
| --- | --- |
| 이벤트 완료 결과 | 성공, 무시, 거부 또는 오류 |
| 다음 dequeue 허용 | pipeline 종료 여부 |

## 6. 구현 기준

| 항목 | 기준 |
| --- | --- |
| 완료 조건 | 필요한 전이와 결과 검사를 끝낸다. |
| 오류 포함 | 진단 정보 생성 후 오류 처리를 종료한다. |
| 외부 작업 비대기 | 비동기 command 완료는 기다리지 않는다. |
| 상태 확정 | 완료 시 current state가 결과와 일치해야 한다. |

## 7. 완료 기준

| 기준 | 확인 방법 |
| --- | --- |
| 무전이 완료 | HANDLED와 IGNORED 종료를 확인한다. |
| 전이 완료 | on_enter 전 다음 dequeue가 없는지 확인한다. |
| 오류 완료 | 오류 기록 후 다음 이벤트를 처리하는지 확인한다. |

# 상태 머신 의존성 보관

## 1. 기능 범위

| 항목 | 내용 |
| --- | --- |
| 기능 ID | `FEAT-STATE-025` |
| 상위 설계 문서 | `ARCH-STATE.md` |
| 관련 설계 항목 | `ARCH-STATE-025` |
| 관련 요구사항 | `REQ-STATE-002` |
| 주요 목적 | 각 상태 머신이 검증한 의존 자원만 자신의 전용 context에 보관한다. |
| 제외 범위 | 상태별 이벤트 처리와 command payload 생성 |

## 2. 연결된 상위 설계 항목

| 설계 항목 ID | 설계 항목 | 연결 내용 |
| --- | --- | --- |
| `ARCH-STATE-025` | 전용 context 의존성 보관 | 각 상태 머신이 자신의 의존성만 검증하고 context에 보관한다. |

## 3. 목적

상태 생명주기가 매번 상위 초기화 인자를 해석하지 않도록, 초기화 시 검증한 자원 참조를 상태 머신의 전용 context에 보관한다.

## 4. 입력

| 입력 | 설명 |
| --- | --- |
| 상태 머신별 InitParams | 해당 머신에 전달된 전용 의존성 |
| 상태 머신 context 저장 공간 | 의존성과 mutable 도메인 데이터를 보관할 정적 수명의 공간 |

## 5. 출력

| 출력 | 설명 |
| --- | --- |
| 초기화된 전용 context | 검증된 handle, port 및 초기 도메인 데이터 |
| 초기화 결과 | 성공 또는 누락되거나 무효한 자원 정보 |

## 6. 구현 기준

| 항목 | 기준 |
| --- | --- |
| 머신별 검증 | 각 상태 머신 초기화 함수가 자신의 필수 InitParams 필드를 검증한다. |
| 참조 복사 | 필요한 handle과 port 참조를 해당 머신의 context에 복사한다. |
| 수명 | context와 context가 참조하는 자원은 상태 머신 운용 중 유효해야 한다. |
| 지역 포인터 금지 | 초기화 함수의 지역 변수나 임시 구조체의 주소를 context에 보관하지 않는다. |
| 의존성 격리 | 다른 상태 머신의 InitParams나 context를 통해 자원에 접근하지 않는다. |

## 7. 완료 기준

| 기준 | 확인 방법 |
| --- | --- |
| 정상 보관 | 전달한 handle과 port가 context에 정확히 보존되는지 확인한다. |
| 누락 거부 | 필수 자원이 누락된 InitParams의 초기화가 실패하는지 확인한다. |
| 수명 안전성 | 초기화 함수 복귀 후에도 context의 자원 참조가 유효한지 확인한다. |
| 격리 | 한 머신이 다른 머신의 context를 통해 자원을 사용하지 않는지 확인한다. |

# FEAT-INPUT-014: 아날로그 조작 이벤트 전송

## 1. 연결된 상위 설계 항목

| 설계 항목 식별자 | 설계 항목 설명 |
| --- | --- |
| `ARCH-INPUT-014` | 조작기 식별자와 값을 하나의 이벤트로 만든다. |
| `ARCH-INPUT-035` | 변환된 입력 이벤트를 발생 순서대로 상태 관리 구조에 전달한다. |

## 2. 설명

조작기 식별자와 원시값, 정규화된 값, 감지 시각을 하나의 아날로그 조작 이벤트로 만들어 `state_event_queue`에 전송한다.

## 3. 입력

| 입력 | 설명 |
| --- | --- |
| 조작기 식별자 | 값을 발생시킨 FX부 또는 트랙부 포텐셔미터 |
| 원시값과 정규화된 값 | 변화 판정과 정규화를 마친 아날로그 값 |
| `TickType_t` | 원본 샘플 감지 시각 |
| `osMessageQueueId_t state_event_queue` | 상태 관리 태스크의 입력 큐 |

## 4. 출력

| 출력 | 설명 |
| --- | --- |
| 아날로그 조작 `StateEvent` | `CONTROL_POT_CHANGE`에 해당하는 상태 이벤트 |
| `osStatus_t` | `state_event_queue` 전송 결과 |

현재 코드에는 `CONTROL_POT_CHANGE`에 대응하는 `StateEventType`과 payload 타입이 없다.

## 5. 구현 기준

| 항목 | 기준 |
| --- | --- |
| 이벤트 계약 | 조작기 식별자, 원시값, 정규화된 값과 감지 시각을 표현할 payload를 정의한다. |
| 전송 | 완성된 `StateEvent`를 `state_event_queue`에 발생 순서대로 보낸다. |
| 실패 처리 | `osMessageQueuePut()`의 반환값을 확인하고 실패를 진단 정보로 남긴다. |
| 책임 제한 | 이벤트가 변경할 FX·트랙 파라미터를 입력 계층에서 결정하지 않는다. |

## 6. 구현 및 검증 상태

| 항목 | 상태 | 날짜 | 비고 |
| --- | --- | --- | --- |
| 구현 | 미구현 | - | 아날로그 `StateEvent` 타입과 payload 및 전송 코드가 없다. |
| 검증 | 미완료 | - | 이벤트 필드, 전송 순서와 큐 포화 처리를 검증한다. |

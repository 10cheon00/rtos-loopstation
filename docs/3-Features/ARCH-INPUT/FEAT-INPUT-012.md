# FEAT-INPUT-012: 아날로그 의미 변화 판정

## 1. 연결된 상위 설계 항목

| 설계 항목 식별자 | 설계 항목 설명 |
| --- | --- |
| `ARCH-INPUT-012` | 최소 변화량과 전송 주기를 적용해 의미 없는 미세 변화와 과도한 이벤트를 제거한다. |
| `ARCH-INPUT-033` | 아날로그 값을 주기적으로 읽고 최소 변화량과 전송 주기를 적용해 의미 있는 변경만 만든다. |

## 2. 설명

현재 ADC 원시값을 조작기별 직전 전송값과 비교해 후속 이벤트를 생성할 의미 있는 변화인지 판정한다.

## 3. 입력

| 입력 | 설명 |
| --- | --- |
| 조작기 식별자 | 변화 판정 상태를 선택하는 포텐셔미터 식별자 |
| 현재 ADC 원시값 | 이번 샘플링에서 읽은 값 |
| 직전 전송값과 시각 | 마지막 이벤트에 사용된 원시값과 RTOS tick |

## 4. 출력

| 출력 | 설명 |
| --- | --- |
| 변화 판정 결과 | 후속 아날로그 이벤트 생성 여부 |
| 확정 원시값 | 최소 변화량 기준을 만족한 현재 값 |

## 5. 구현 기준

| 항목 | 기준 |
| --- | --- |
| 변화량 | 조작기별 최소 변화량 이상인 경우에만 의미 있는 변화로 판정한다. |
| 전송 주기 | 연속 조작 중에도 설정한 최소 전송 간격보다 자주 이벤트를 만들지 않는다. |
| 상태 분리 | 각 조작기의 직전 값과 시각을 독립적으로 보관한다. |
| 경계 처리 | ADC 범위 양 끝에서도 차이 계산의 overflow가 없어야 한다. |

## 6. 구현 및 검증 상태

| 항목 | 상태 | 날짜 | 비고 |
| --- | --- | --- | --- |
| 구현 | 미구현 | - | 조작기별 직전 값, threshold와 전송 주기 판정이 없다. |
| 검증 | 미완료 | - | 정지 노이즈, 느린 조작, 빠른 연속 조작으로 검증한다. |

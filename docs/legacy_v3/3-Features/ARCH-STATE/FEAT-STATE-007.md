# 상태 이벤트 queue 수신

## 1. 기능 범위

| 항목 | 내용 |
| --- | --- |
| 기능 ID | `FEAT-STATE-007` |
| 상위 설계 문서 | `ARCH-STATE.md` |
| 관련 설계 항목 | `ARCH-STATE-007` |
| 관련 요구사항 | `REQ-STATE-003` |
| 주요 목적 | 상태 관리 태스크가 state_event_queue의 단일 소비자로 blocking 대기하고 이벤트를 순서대로 읽는다. |
| 제외 범위 | queue 생성과 이벤트 생산자 구현 |

## 2. 연결된 상위 설계 항목

| 설계 항목 ID | 설계 항목 | 연결 내용 |
| --- | --- | --- |
| `ARCH-STATE-007` | 상태 이벤트 수신 | 상태 관리 태스크가 state_event_queue의 단일 소비자로 blocking 대기하고 이벤트를 순서대로 읽는다. |

## 3. 목적

상태 관리 태스크가 state_event_queue의 단일 소비자로 blocking 대기하고 이벤트를 순서대로 읽는다.

## 4. 입력

| 입력 | 설명 |
| --- | --- |
| state_event_queue handle | CubeMX가 생성한 queue |
| StateEvent 저장 공간 | dequeue 결과 수신 버퍼 |

## 5. 출력

| 출력 | 설명 |
| --- | --- |
| StateEvent | queue에서 꺼낸 이벤트 |
| 수신 결과 | 성공, timeout 또는 RTOS 오류 |

## 6. 구현 기준

| 항목 | 기준 |
| --- | --- |
| 단일 소비자 | 상태 관리 태스크만 dequeue한다. |
| blocking 대기 | 이벤트가 없을 때 polling하지 않는다. |
| 반환값 확인 | 수신 성공 후에만 메시지를 사용한다. |
| 크기 일치 | queue 원소 크기와 StateEvent 크기가 일치해야 한다. |

## 7. 완료 기준

| 기준 | 확인 방법 |
| --- | --- |
| 대기 동작 | 빈 queue에서 태스크가 block되는지 확인한다. |
| 순서 보존 | 연속 이벤트가 FIFO로 수신되는지 확인한다. |
| 수신 오류 | 실패 시 미초기화 이벤트를 처리하지 않는지 확인한다. |

# 상태 처리 결과 검사

## 1. 기능 범위

| 항목 | 내용 |
| --- | --- |
| 기능 ID | `FEAT-STATE-019` |
| 상위 설계 문서 | `ARCH-STATE.md` |
| 관련 설계 항목 | `ARCH-STATE-019` |
| 관련 요구사항 | `REQ-STATE-006` |
| 주요 목적 | on_message 결과를 검사해 완료, 전이, 상태 유지 또는 오류 경로를 선택한다. |
| 제외 범위 | 각 상태의 결과 생성과 최종 오류 전달 |

## 2. 연결된 상위 설계 항목

| 설계 항목 ID | 설계 항목 | 연결 내용 |
| --- | --- | --- |
| `ARCH-STATE-019` | 결과 확인 | on_message 결과를 검사해 완료, 전이, 상태 유지 또는 오류 경로를 선택한다. |

## 3. 목적

on_message 결과를 검사해 완료, 전이, 상태 유지 또는 오류 경로를 선택한다.

## 4. 입력

| 입력 | 설명 |
| --- | --- |
| State handling result | 검사 대상 |
| 상태 머신 인스턴스 | 전이 및 보존 대상 |
| StateEvent | 진단용 원본 이벤트 |

## 5. 출력

| 출력 | 설명 |
| --- | --- |
| 후속 처리 선택 | 완료, 전이 검증, 유지 또는 오류 |
| 최종 이벤트 결과 | 처리 loop 기록값 |

## 6. 구현 기준

| 항목 | 기준 |
| --- | --- |
| 전체 분기 | 모든 결과 enum을 처리한다. |
| default 오류 | 알 수 없는 값은 ERROR로 본다. |
| TRANSITION 경로 | 검증과 전이 executor를 호출한다. |
| 무변경 경로 | IGNORED와 REJECTED는 전이하지 않는다. |

## 7. 완료 기준

| 기준 | 확인 방법 |
| --- | --- |
| 분기 커버리지 | 다섯 결과의 경로를 확인한다. |
| 알 수 없는 값 | 손상 enum이 ERROR인지 확인한다. |
| 전이 조건 | TRANSITION 외에는 executor가 호출되지 않는지 확인한다. |

## 8. 구현 및 검증 상태

| 항목 | 상태 | 날짜 | 비고 |
| --- | --- | --- | --- |
| 구현 | 미구현 | - | 기능 명세에 따른 구현이 필요하다. |
| 검증 | 미검증 | - | 구현 완료 후 완료 기준에 따라 검증한다. |

# 공통 상태 전이 실행

## 1. 기능 범위

| 항목 | 내용 |
| --- | --- |
| 기능 ID | `FEAT-STATE-014` |
| 상위 설계 문서 | `ARCH-STATE.md` |
| 관련 설계 항목 | `ARCH-STATE-014` |
| 관련 요구사항 | `REQ-STATE-004` |
| 주요 목적 | 검증된 전이를 on_exit, current state 변경, on_enter 순서로 실행한다. |
| 제외 범위 | on_message 발생 경로와 생명주기 내부 로직 |

## 2. 연결된 상위 설계 항목

| 설계 항목 ID | 설계 항목 | 연결 내용 |
| --- | --- | --- |
| `ARCH-STATE-014` | 공통 전이 순서 | 검증된 전이를 on_exit, current state 변경, on_enter 순서로 실행한다. |

## 3. 목적

검증된 전이를 on_exit, current state 변경, on_enter 순서로 실행한다.

## 4. 입력

| 입력 | 설명 |
| --- | --- |
| 상태 머신 인스턴스 | 전이 대상 |
| 현재 및 다음 상태 | 검증된 참조 |
| 전이 원인 | 생명주기 입력 |

## 5. 출력

| 출력 | 설명 |
| --- | --- |
| 전이 결과 | 성공 또는 실패 단계 |
| 갱신된 현재 상태 | 목적 상태 참조 |

## 6. 구현 기준

| 항목 | 기준 |
| --- | --- |
| 호출 순서 | on_exit 후 commit하고 on_enter를 호출한다. |
| 검증 전제 | 검증된 요청만 실행한다. |
| 단일 변경 | current state를 한 번만 쓴다. |
| 오류 단계 | 실패한 생명주기 단계를 반환한다. |

## 7. 완료 기준

| 기준 | 확인 방법 |
| --- | --- |
| 순서 기록 | mock으로 호출 순서를 확인한다. |
| 단일 commit | 쓰기 횟수가 한 번인지 확인한다. |
| 실패 결과 | 각 단계 오류가 구분되는지 확인한다. |

| 항목 | 상태 | 날짜 | 비고 |

| 검증 | 미검증 | - | 구현 완료 후 완료 기준에 따라 검증한다. |

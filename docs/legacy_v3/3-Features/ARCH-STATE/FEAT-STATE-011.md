# 공통 상태 생명주기 정의

## 1. 기능 범위

| 항목 | 내용 |
| --- | --- |
| 기능 ID | `FEAT-STATE-011` |
| 상위 설계 문서 | `ARCH-STATE.md` |
| 관련 설계 항목 | `ARCH-STATE-011` |
| 관련 요구사항 | `REQ-STATE-004` |
| 주요 목적 | on_enter, on_message, on_exit의 책임과 금지 사항을 공통 계약으로 정의한다. |
| 제외 범위 | C 함수 포인터 타입과 도메인별 생명주기 구현 |

## 2. 연결된 상위 설계 항목

| 설계 항목 ID | 설계 항목 | 연결 내용 |
| --- | --- | --- |
| `ARCH-STATE-011` | 공통 생명주기 | on_enter, on_message, on_exit의 책임과 금지 사항을 공통 계약으로 정의한다. |

## 3. 목적

on_enter, on_message, on_exit의 책임과 금지 사항을 공통 계약으로 정의한다.

## 4. 입력

| 입력 | 설명 |
| --- | --- |
| 상태 머신 context | 인스턴스 데이터 |
| 이벤트 또는 전이 원인 | 생명주기 호출 입력 |

## 5. 출력

| 출력 | 설명 |
| --- | --- |
| 생명주기 처리 결과 | 호출 성공 또는 오류 |
| context 변화 | 진입과 이탈에 따른 내부 변화 |

## 6. 구현 기준

| 항목 | 기준 |
| --- | --- |
| on_enter | 새 상태 진입 값을 준비하고 current state를 직접 바꾸지 않는다. |
| on_message | 이벤트를 처리하고 공통 결과를 반환한다. |
| on_exit | 현재 상태를 정리하고 다음 on_enter를 직접 호출하지 않는다. |
| 상호 변경 금지 | 다른 머신의 canonical state를 직접 바꾸지 않는다. |

## 7. 완료 기준

| 기준 | 확인 방법 |
| --- | --- |
| 계약 문서화 | 공개 인터페이스에 책임과 제한이 명시되는지 확인한다. |
| 상태 구현 검토 | 대표 구현이 계약을 따르는지 확인한다. |
| 금지 동작 | 직접 상태 쓰기와 다음 상태 직접 호출이 없는지 확인한다. |

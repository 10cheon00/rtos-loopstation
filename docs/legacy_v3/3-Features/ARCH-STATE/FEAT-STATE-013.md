# 상태 전이 요청 검증

## 1. 기능 범위

| 항목 | 내용 |
| --- | --- |
| 기능 ID | `FEAT-STATE-013` |
| 상위 설계 문서 | `ARCH-STATE.md` |
| 관련 설계 항목 | `ARCH-STATE-013` |
| 관련 요구사항 | `REQ-STATE-004` |
| 주요 목적 | TRANSITION의 다음 상태가 대상 상태 머신에 등록된 유효한 상태인지 확인한다. |
| 제외 범위 | 도메인별 이벤트 허용 판단과 실제 commit |

## 2. 연결된 상위 설계 항목

| 설계 항목 ID | 설계 항목 | 연결 내용 |
| --- | --- | --- |
| `ARCH-STATE-013` | 전이 요청 검증 | TRANSITION의 다음 상태가 대상 상태 머신에 등록된 유효한 상태인지 확인한다. |

## 3. 목적

TRANSITION의 다음 상태가 대상 상태 머신에 등록된 유효한 상태인지 확인한다.

## 4. 입력

| 입력 | 설명 |
| --- | --- |
| 상태 머신 인스턴스 | 허용 상태 집합 소유자 |
| 현재 상태 | 전이 출발 상태 |
| 다음 상태 | 전이 목적 상태 |

## 5. 출력

| 출력 | 설명 |
| --- | --- |
| 전이 검증 결과 | valid 또는 오류 |
| 검증된 다음 상태 | commit 대상 |

## 6. 구현 기준

| 항목 | 기준 |
| --- | --- |
| 소속 검사 | 다음 상태는 허용 집합에 있어야 한다. |
| null 검사 | null 목적 상태를 거부한다. |
| 동일 상태 정책 | self transition 규칙을 명시한다. |
| 부작용 금지 | 실패 시 on_exit과 commit을 실행하지 않는다. |

## 7. 완료 기준

| 기준 | 확인 방법 |
| --- | --- |
| 정상 전이 | 등록 상태가 valid인지 확인한다. |
| 외부 상태 | 다른 머신 상태가 거부되는지 확인한다. |
| 실패 무변경 | 검증 실패 후 상태가 유지되는지 확인한다. |

## 8. 구현 및 검증 상태

| 항목 | 상태 | 날짜 | 비고 |
| --- | --- | --- | --- |
| 구현 | 미구현 | - | 기능 명세에 따른 구현이 필요하다. |
| 검증 | 미검증 | - | 구현 완료 후 완료 기준에 따라 검증한다. |

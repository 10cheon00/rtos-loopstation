| --- | --- |
| 기능 ID | `FEAT-STATE-012` |
| 상위 설계 문서 | `ARCH-STATE.md` |

## 3. 목적

구체 상태 타입을 몰라도 공통 함수 시그니처로 세 생명주기를 호출할 수 있게 한다.

## 4. 입력

| 입력 | 설명 |
| --- | --- |
| 상태 인터페이스 정의 | 상태 ID와 함수 포인터 |
| context view | 상태 머신 데이터 |
| 이벤트 또는 전이 원인 | 호출 입력 |

## 5. 출력

| 출력 | 설명 |
| --- | --- |
| State interface 객체 | 정적 상태 정의 |
| 공통 결과 타입 | 생명주기 반환값 |

## 6. 구현 기준

| 항목 | 기준 |
| --- | --- |
| 시그니처 통일 | 모든 상태가 같은 함수 타입을 사용한다. |
| const 적용 | 상태 정의는 읽기 전용으로 전달한다. |
| context 명시 | mutable 데이터는 context에 저장한다. |
| 필수 함수 정책 | null 금지 또는 no-op 정책을 일관되게 적용한다. |

## 7. 완료 기준

| 기준 | 확인 방법 |
| --- | --- |
| 컴파일 호환 | 서로 다른 상태를 같은 배열에 등록하는지 확인한다. |
| 호출 호환 | 구체 타입 cast 없이 호출되는지 확인한다. |
| const 검증 | 상태 정의가 런타임에 수정되지 않는지 확인한다. |

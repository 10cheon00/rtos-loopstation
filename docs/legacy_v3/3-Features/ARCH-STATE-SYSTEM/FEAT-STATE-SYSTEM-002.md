# 시스템 초기 상태

## 1. 기능 범위

| 항목 | 내용 |
| --- | --- |
| 기능 ID | `FEAT-STATE-SYSTEM-002` |
| 상위 설계 문서 | `ARCH-STATE-SYSTEM.md` |
| 관련 설계 항목 | `ARCH-STATE-SYSTEM-002` |
| 관련 요구사항 | `REQ-STATE-SYSTEM-001` |
| 주요 목적 | 전원 인가 직후의 상태를 고정한다. |
| 제외 범위 | SYSTEM_START 처리와 INIT 진입 |

## 2. 연결된 상위 설계 항목

| 설계 항목 ID | 설계 항목 | 연결 내용 |
| --- | --- | --- |
| `ARCH-STATE-SYSTEM-002` | 시스템 초기 상태 | 초기 상태 참조를 `NOT_INIT`으로 등록한다. |

## 3. 목적

전원 인가 직후의 상태를 고정한다.
이를 위해 초기 상태 참조를 `NOT_INIT`으로 등록한다.

## 4. 입력

| 입력 | 설명 |
| --- | --- |
| 시스템 상태 머신 등록 정보 | 초기 상태와 system context |

## 5. 출력

| 출력 | 설명 |
| --- | --- |
| 초기 상태 참조 | NOT_INIT을 가리키는 시스템 인스턴스 |

## 6. 구현 기준

| 항목 | 기준 |
| --- | --- |
| 설계 결정 | 초기 상태 참조를 `NOT_INIT`으로 등록한다. |
| 초기값 고정 | 초기 current state는 반드시 NOT_INIT이어야 한다. |
| 오류 처리 | 입력이나 현재 상태가 유효하지 않으면 canonical state를 변경하지 않고 명시적 오류 또는 거부 결과를 반환해야 한다. |
| 실행 문맥 | 상태 관리 태스크의 이벤트 처리 경로에서 무제한 blocking과 동적 메모리 할당 없이 실행해야 한다. |

## 7. 완료 기준

| 기준 | 확인 방법 |
| --- | --- |
| 초기 상태 | 등록 직후 current state가 NOT_INIT인지 확인한다. |
| 오류 경로 | 잘못된 입력에서 상태가 훼손되지 않고 정의된 실패 결과가 반환되는지 확인한다. |
| 설계 추적 | 구현과 시험이 `ARCH-STATE-SYSTEM-002`의 설계 결정을 만족하는지 검토한다. |

# cleanup 시작

## 1. 기능 범위

| 항목 | 내용 |
| --- | --- |
| 기능 ID | `FEAT-STATE-SYSTEM-020` |
| 상위 설계 문서 | `ARCH-STATE-SYSTEM.md` |
| 관련 설계 항목 | `ARCH-STATE-SYSTEM-020` |
| 관련 요구사항 | `REQ-STATE-SYSTEM-009` |
| 주요 목적 | 사용 중인 자원의 정리를 요청한다. |
| 제외 범위 | 대상별 cleanup 구현 |

## 2. 연결된 상위 설계 항목

| 설계 항목 ID | 설계 항목 | 연결 내용 |
| --- | --- | --- |
| `ARCH-STATE-SYSTEM-020` | cleanup 시작 | `END.on_enter`에서 오디오 정지, 파일 finalize와 표시 종료 처리를 요청한다. |

## 3. 목적

사용 중인 자원의 정리를 요청한다.
이를 위해 `END.on_enter`에서 오디오 정지, 파일 finalize와 표시 종료 처리를 요청한다.

## 4. 입력

| 입력 | 설명 |
| --- | --- |
| END 진입 원인 | shutdown request |
| cleanup 대상 목록 | 오디오, 저장과 표시 정리 항목 |

## 5. 출력

| 출력 | 설명 |
| --- | --- |
| cleanup 요청 | 대상별 정리 command |
| cleanup context | pending 상태 목록 |

## 6. 구현 기준

| 항목 | 기준 |
| --- | --- |
| 설계 결정 | END.on_enter`에서 오디오 정지, 파일 finalize와 표시 종료 처리를 요청한다. |
| 요청 누락 방지 | 모든 필수 cleanup 대상을 pending으로 등록한 뒤 요청해야 한다. |
| 오류 처리 | 입력이나 현재 상태가 유효하지 않으면 canonical state를 변경하지 않고 명시적 오류 또는 거부 결과를 반환해야 한다. |
| 실행 문맥 | 상태 관리 태스크의 이벤트 처리 경로에서 무제한 blocking과 동적 메모리 할당 없이 실행해야 한다. |

## 7. 완료 기준

| 기준 | 확인 방법 |
| --- | --- |
| cleanup 시작 | END 진입 시 필수 대상 전체에 요청되는지 확인한다. |
| 오류 경로 | 잘못된 입력에서 상태가 훼손되지 않고 정의된 실패 결과가 반환되는지 확인한다. |
| 설계 추적 | 구현과 시험이 `ARCH-STATE-SYSTEM-020`의 설계 결정을 만족하는지 검토한다. |

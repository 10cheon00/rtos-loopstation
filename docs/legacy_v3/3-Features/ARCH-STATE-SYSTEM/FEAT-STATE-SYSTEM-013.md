# 상태 머신 활성화

## 1. 기능 범위

| 항목 | 내용 |
| --- | --- |
| 기능 ID | `FEAT-STATE-SYSTEM-013` |
| 상위 설계 문서 | `ARCH-STATE-SYSTEM.md` |
| 관련 설계 항목 | `ARCH-STATE-SYSTEM-013` |
| 관련 요구사항 | `REQ-STATE-SYSTEM-006` |
| 주요 목적 | 정상 실행 진입 시 도메인 상태 머신의 생명주기를 시작한다. |
| 제외 범위 | 각 도메인 상태 머신의 초기 상태 선정 |

## 2. 연결된 상위 설계 항목

| 설계 항목 ID | 설계 항목 | 연결 내용 |
| --- | --- | --- |
| `ARCH-STATE-SYSTEM-013` | 상태 머신 활성화 | `RUNNING.on_enter` 완료 후 등록된 일반 상태 머신의 초기 진입을 허용한다. |

## 3. 목적

정상 실행 진입 시 도메인 상태 머신의 생명주기를 시작한다.
이를 위해 `RUNNING.on_enter` 완료 후 등록된 일반 상태 머신의 초기 진입을 허용한다.

## 4. 입력

| 입력 | 설명 |
| --- | --- |
| RUNNING 진입 완료 | system on_enter 성공 결과 |
| 상태 머신 등록부 | 활성화할 일반 상태 머신 목록 |

## 5. 출력

| 출력 | 설명 |
| --- | --- |
| 활성화 결과 | 머신별 최초 진입 성공 또는 오류 |

## 6. 구현 기준

| 항목 | 기준 |
| --- | --- |
| 설계 결정 | `RUNNING.on_enter` 완료 후 등록된 일반 상태 머신의 초기 진입을 허용한다. |
| 진입 후 실행 | `RUNNING.on_enter` 완료 전에는 일반 상태 머신을 활성화하지 않아야 한다. |
| 오류 처리 | 입력이나 현재 상태가 유효하지 않으면 canonical state를 변경하지 않고 명시적 오류 또는 거부 결과를 반환해야 한다. |
| 실행 문맥 | 상태 관리 태스크의 이벤트 처리 경로에서 무제한 blocking과 동적 메모리 할당 없이 실행해야 한다. |

## 7. 완료 기준

| 기준 | 확인 방법 |
| --- | --- |
| 활성화 순서 | RUNNING 진입 완료 후에만 각 머신 최초 on_enter가 호출되는지 확인한다. |
| 오류 경로 | 잘못된 입력에서 상태가 훼손되지 않고 정의된 실패 결과가 반환되는지 확인한다. |
| 설계 추적 | 구현과 시험이 `ARCH-STATE-SYSTEM-013`의 설계 결정을 만족하는지 검토한다. |

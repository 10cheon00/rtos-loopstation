# 기능 차단

## 1. 기능 범위

| 항목 | 내용 |
| --- | --- |
| 기능 ID | `FEAT-STATE-SYSTEM-016` |
| 상위 설계 문서 | `ARCH-STATE-SYSTEM.md` |
| 관련 설계 항목 | `ARCH-STATE-SYSTEM-016` |
| 관련 요구사항 | `REQ-STATE-SYSTEM-010` |
| 주요 목적 | 오류 상태에서 추가 동작이 실행되는 것을 막는다. |
| 제외 범위 | ERROR 진입 직후 안전 정지 command |

## 2. 연결된 상위 설계 항목

| 설계 항목 ID | 설계 항목 | 연결 내용 |
| --- | --- | --- |
| `ARCH-STATE-SYSTEM-016` | 기능 차단 | `ERROR`에서는 진단과 종료 정책 이외의 이벤트를 `REJECTED`로 처리한다. |

## 3. 목적

오류 상태에서 추가 동작이 실행되는 것을 막는다.
이를 위해 `ERROR`에서는 진단과 종료 정책 이외의 이벤트를 `REJECTED`로 처리한다.

## 4. 입력

| 입력 | 설명 |
| --- | --- |
| ERROR 상태의 StateEvent | 일반, 진단 또는 종료 정책 이벤트 |

## 5. 출력

| 출력 | 설명 |
| --- | --- |
| 상태 처리 결과 | REJECTED 또는 허용된 정책 결과 |

## 6. 구현 기준

| 항목 | 기준 |
| --- | --- |
| 설계 결정 | `ERROR`에서는 진단과 종료 정책 이외의 이벤트를 `REJECTED`로 처리한다. |
| 허용 목록 | `ERROR`에서 처리할 진단 및 종료 정책 이벤트를 명시적 allowlist로 관리해야 한다. |
| 오류 처리 | 입력이나 현재 상태가 유효하지 않으면 canonical state를 변경하지 않고 명시적 오류 또는 거부 결과를 반환해야 한다. |
| 실행 문맥 | 상태 관리 태스크의 이벤트 처리 경로에서 무제한 blocking과 동적 메모리 할당 없이 실행해야 한다. |

## 7. 완료 기준

| 기준 | 확인 방법 |
| --- | --- |
| 기능 차단 | 일반 녹음, 재생, 저장 이벤트가 `ERROR`에서 거부되는지 확인한다. |
| 오류 경로 | 잘못된 입력에서 상태가 훼손되지 않고 정의된 실패 결과가 반환되는지 확인한다. |
| 설계 추적 | 구현과 시험이 `ARCH-STATE-SYSTEM-016`의 설계 결정을 만족하는지 검토한다. |

# 오류 상태 전이

## 1. 기능 범위

| 항목 | 내용 |
| --- | --- |
| 기능 ID | `FEAT-STATE-SYSTEM-015` |
| 상위 설계 문서 | `ARCH-STATE-SYSTEM.md` |
| 관련 설계 항목 | `ARCH-STATE-SYSTEM-015` |
| 관련 요구사항 | `REQ-STATE-SYSTEM-007` |
| 주요 목적 | 복구 불가능한 시스템 동작을 중단한다. |
| 제외 범위 | ERROR.on_enter의 안전 정지와 표시 |

## 2. 연결된 상위 설계 항목

| 설계 항목 ID | 설계 항목 | 연결 내용 |
| --- | --- | --- |
| `ARCH-STATE-SYSTEM-015` | 오류 상태 전이 | `INIT`과 `RUNNING`에서 `SYSTEM_FATAL_ERROR` 수신 시 `ERROR`로 전이한다. |

## 3. 목적

복구 불가능한 시스템 동작을 중단한다.
이를 위해 `INIT`과 `RUNNING`에서 `SYSTEM_FATAL_ERROR` 수신 시 `ERROR`로 전이한다.

## 4. 입력

| 입력 | 설명 |
| --- | --- |
| SYSTEM_FATAL_ERROR 이벤트 | 정규화된 치명 오류 |
| 현재 시스템 상태 | INIT 또는 RUNNING |

## 5. 출력

| 출력 | 설명 |
| --- | --- |
| 상태 처리 결과 | TRANSITION(ERROR) |

## 6. 구현 기준

| 항목 | 기준 |
| --- | --- |
| 설계 결정 | `INIT`과 `RUNNING`에서 `SYSTEM_FATAL_ERROR` 수신 시 `ERROR`로 전이한다. |
| 출발 상태 | INIT과 RUNNING에서만 정의된 오류 전이를 수행해야 한다. |
| 오류 처리 | 입력이나 현재 상태가 유효하지 않으면 canonical state를 변경하지 않고 명시적 오류 또는 거부 결과를 반환해야 한다. |
| 실행 문맥 | 상태 관리 태스크의 이벤트 처리 경로에서 무제한 blocking과 동적 메모리 할당 없이 실행해야 한다. |

## 7. 완료 기준

| 기준 | 확인 방법 |
| --- | --- |
| 오류 전이 | INIT과 RUNNING 모두 ERROR 전이를 반환하는지 확인한다. |
| 오류 경로 | 잘못된 입력에서 상태가 훼손되지 않고 정의된 실패 결과가 반환되는지 확인한다. |
| 설계 추적 | 구현과 시험이 `ARCH-STATE-SYSTEM-015`의 설계 결정을 만족하는지 검토한다. |

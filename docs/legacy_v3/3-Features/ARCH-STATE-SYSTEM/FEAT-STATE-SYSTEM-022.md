# 시스템 동작 종료

## 1. 기능 범위

| 항목 | 내용 |
| --- | --- |
| 기능 ID | `FEAT-STATE-SYSTEM-022` |
| 상위 설계 문서 | `ARCH-STATE-SYSTEM.md` |
| 관련 설계 항목 | `ARCH-STATE-SYSTEM-022` |
| 관련 요구사항 | `REQ-STATE-SYSTEM-009` |
| 주요 목적 | cleanup 후 기능 처리를 끝낸다. |
| 제외 범위 | MCU 전원 차단, reset 또는 저전력 방식 결정 |

## 2. 연결된 상위 설계 항목

| 설계 항목 ID | 설계 항목 | 연결 내용 |
| --- | --- | --- |
| `ARCH-STATE-SYSTEM-022` | 시스템 동작 종료 | 모든 필수 cleanup이 종료되면 일반 이벤트 수신을 중단하고 플랫폼 종료 절차를 호출한다. |

## 3. 목적

cleanup 후 기능 처리를 끝낸다.
이를 위해 모든 필수 cleanup이 종료되면 일반 이벤트 수신을 중단하고 플랫폼 종료 절차를 호출한다.

## 4. 입력

| 입력 | 설명 |
| --- | --- |
| cleanup 완료 판정 | 모든 필수 대상 종료 |
| 플랫폼 종료 port | 종료 절차 인터페이스 |

## 5. 출력

| 출력 | 설명 |
| --- | --- |
| 시스템 동작 종료 결과 | 호출 성공 또는 오류 |
| 이벤트 처리 상태 | 일반 이벤트 수신 중단 |

## 6. 구현 기준

| 항목 | 기준 |
| --- | --- |
| 설계 결정 | 모든 필수 cleanup이 종료되면 일반 이벤트 수신을 중단하고 플랫폼 종료 절차를 호출한다. |
| 호출 순서 | 일반 이벤트 처리를 중단한 뒤 플랫폼 종료 절차를 호출해야 한다. |
| 오류 처리 | 입력이나 현재 상태가 유효하지 않으면 canonical state를 변경하지 않고 명시적 오류 또는 거부 결과를 반환해야 한다. |
| 실행 문맥 | 상태 관리 태스크의 이벤트 처리 경로에서 무제한 blocking과 동적 메모리 할당 없이 실행해야 한다. |

## 7. 완료 기준

| 기준 | 확인 방법 |
| --- | --- |
| 최종 종료 | cleanup 완료 전에는 호출되지 않고 완료 후 한 번 호출되는지 확인한다. |
| 오류 경로 | 잘못된 입력에서 상태가 훼손되지 않고 정의된 실패 결과가 반환되는지 확인한다. |
| 설계 추적 | 구현과 시험이 `ARCH-STATE-SYSTEM-022`의 설계 결정을 만족하는지 검토한다. |

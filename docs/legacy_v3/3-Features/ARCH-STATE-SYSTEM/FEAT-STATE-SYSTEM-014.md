# 치명 오류 이벤트

## 1. 기능 범위

| 항목 | 내용 |
| --- | --- |
| 기능 ID | `FEAT-STATE-SYSTEM-014` |
| 상위 설계 문서 | `ARCH-STATE-SYSTEM.md` |
| 관련 설계 항목 | `ARCH-STATE-SYSTEM-014` |
| 관련 요구사항 | `REQ-STATE-SYSTEM-007` |
| 주요 목적 | 오류 발생 위치와 무관하게 시스템 오류 전이를 요청한다. |
| 제외 범위 | 복구 가능 오류 처리와 사용자 표시 |

## 2. 연결된 상위 설계 항목

| 설계 항목 ID | 설계 항목 | 연결 내용 |
| --- | --- | --- |
| `ARCH-STATE-SYSTEM-014` | 치명 오류 이벤트 | `SYSTEM_FATAL_ERROR`에 오류 원인과 발생 주체를 포함한다. |

## 3. 목적

오류 발생 위치와 무관하게 시스템 오류 전이를 요청한다.
이를 위해 `SYSTEM_FATAL_ERROR`에 오류 원인과 발생 주체를 포함한다.

## 4. 입력

| 입력 | 설명 |
| --- | --- |
| 오류 감지 정보 | 발생 주체, 오류 code와 심각도 |

## 5. 출력

| 출력 | 설명 |
| --- | --- |
| SYSTEM_FATAL_ERROR 이벤트 | 정규화된 치명 오류 payload |

## 6. 구현 기준

| 항목 | 기준 |
| --- | --- |
| 설계 결정 | `SYSTEM_FATAL_ERROR`에 오류 원인과 발생 주체를 포함한다. |
| 정보 보존 | 발생 주체와 오류 code를 값으로 복사해 이벤트 수명 동안 유지해야 한다. |
| 오류 처리 | 입력이나 현재 상태가 유효하지 않으면 canonical state를 변경하지 않고 명시적 오류 또는 거부 결과를 반환해야 한다. |
| 실행 문맥 | 상태 관리 태스크의 이벤트 처리 경로에서 무제한 blocking과 동적 메모리 할당 없이 실행해야 한다. |

## 7. 완료 기준

| 기준 | 확인 방법 |
| --- | --- |
| 이벤트 생성 | 대표 치명 오류가 필수 정보를 포함한 이벤트로 변환되는지 확인한다. |
| 오류 경로 | 잘못된 입력에서 상태가 훼손되지 않고 정의된 실패 결과가 반환되는지 확인한다. |
| 설계 추적 | 구현과 시험이 `ARCH-STATE-SYSTEM-014`의 설계 결정을 만족하는지 검토한다. |

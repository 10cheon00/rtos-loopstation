# StateTask 파이프라인 재구성

엔코더 입력을 구현하려고 생각하니 패널에서 커서를 움직이고 이를 반영해야한다면 커서값을 어딘가에 저장해야겠다고 생각했다. 그런데 커서값을 파라미터로 다루면 시스템이 간단해질것 같았다. 파라미터는 FX 파라미터와 같이 그냥 설정값 형태로 관리하면 굳이 각 패널마다 커서 위치를 기억하지 않아도 쉽게 관리할 수 있을 것 같았다. 

그러려면 일단 설정값 저장소가 필요해서 싱글톤으로 간단히 구현했다. 그리고 엔코더 방향 및 버튼 홀딩 유무에 따라 스케일을 다르게 줘서 파라미터를 수정할 수 있도록 했다. 어떤 파라미터를 수정해야하는지는 미리 정의한 config에 의해서 탐색할 수 있도록 `types/`밑에 고유한 식별자들을 정의하고 그 식별자들을 이용해 매핑이나 바인딩용 구조체를 만들었다. 

이렇게 하니까 디스플레이 상태 머신의 각 상태 안에서 컨텍스트를 유지할 필요가 없어졌다. 단순히 출력하라고만 하면 명령 큐를 사용해 출력한다. 명령 큐에 들어갈 메시지도 구체적으로 어떻게 출력해라 대신에 고유한 식별자와 출력해야할 파라미터 값만 넘겨주면 된다. 어떻게 출력할지는 디스플레이 태스크의 몫이다. 이렇게 생각하니 디스플레이 상태 머신은 사실상 현재 어떤 ui에 있는지만 나타내게 되었다. 그래서 각 상태가 고유한 식별자를 가지기만 하도록 만들고, StateTask에서는 현재 디스플레이 상태가 무엇인지만 참조하게 되었다. 즉, 이벤트를 받아서 어떤 상태로 전이해야 하는지만 남았다. 그래서 이름을 디스플레이 상태 머신에서 UI 상태 머신으로 변경했다.

`StateEvent`를 처리하는 모든 함수의 반환값을 `TaskStatus`가 아니라 `StateOnEventResultFlags`로 변경했다. 사실 `StateEventResultFlags`로 바꾸는게 더 맞는 것 같다.

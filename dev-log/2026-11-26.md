# state_task 리팩토링

마냥 기다리기만 뭐해서 너무 길게 느껴졌던 state_task를 리팩토링하기로 했다. 상태 관리 태스크가 하는 일은 입력 이벤트 태스크가 전달한 이벤트 메시지를 수신, 처리 후 오디오 태스크와 디스플레이 태스크에 결과를 전달하거나 상태를 업데이트한다. 이번 리팩토링의 중점은 메시지를 처리하는 것만 하위 모듈에 전달하는 형태로 두어 `Run()` 함수를 깔끔하게 유지하고자 했다.

parameter_updater.cpp를 만들고, 변환된 입력 이벤트를 분류, 처리하는 기존 코드들을 해당 파일로 옮겼다. 옮기고 보니 상태 관리 태스크의 내부 변수에 깊게 결합된 것을 알 수 있었다. 결합된 데이터를 인자로 넘기되 입력 이벤트 종류에 따라서 필요한 데이터만 넘기도록 했다. 이벤트 종류는 std::variant가 보관하고 있는 타입을 검사할 수 있는 std::visit를 사용했다. 

처음에는 상태 관리 태스크에서 StateEventVariant 참조를 하위 모듈에 던지면 모듈이 variant를 해석하고 보관하고 있는 타입에 따라 분기하도록 구현했다. 그렇게 하니 버튼 입력에 따라 상태 관리 태스크 내에서 처리되어야 할 작업들도 하위 모듈이 담당하게 되었다. 하위 모듈의 책임은 이벤트를 읽어서 파라미터 저장소에 업데이트 하는 것인데, 상태 관리 태스크의 일부 작업도 가져가는 셈이 되었다. 그래서 입력 이벤트 종류 해석은 상태 관리 태스크에서 하고, 이벤트 종류에 따라 어떻게 파라미터 저장소에 업데이트하는지는 하위 모듈이 담당하도록 재구성했다. 리팩토링 과정에서 variant를 처리할 때 C++ 문법을 활용하는 방법은 AI로부터 얻었다.

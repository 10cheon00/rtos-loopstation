# Adc 변환 태스크 추가

Adc를 인터럽트로 받자니, n 사이클마다 인터럽트가 발생하니까 발생 빈도가 높을 것이라고 생각했다. 그래서 인터럽트를 발생시키는 대신, 간단하게 0.n초마다 주기적으로 Adc를 폴링하기로 했다. 인터럽트로 처리하는 것보다 훨씬 코드가 간단하고 CPU 점유율도 낮다. 주기를 0.1초로 설정해 100hz의 클럭으로 adc를 폴링한 후 InputTask에 메시지를 전송하도록 구현했다. 아직 파라미터를 출력할 패널이나 파라미터를 적용할 옵션을 만들지 않아서 라이브 워치로 확인만 했다.

# mcp23017 led 출력 구현

mcp23017으로 입력만 받고 있었는데, IFX / TFX 상태를 LED로 나타내야해서 DisplayTask에도 mcp23017.h를 쓸 수 있어야 했다. 기존에 InputTask에서 mcp23017에 대한 정보를 갖고 있었지만 입력에 관한 정보만 있었고, 현재까지 정해진 코드 스타일대로 구현되어 있지 않아서, 입력과 출력에 대한 정보를 모두 가진 설정 파일을 만들고 DisplayTask와 InputTask 모두 이 설정 파일을 쓰도록 정리했다.

# 디스플레이 출력 딜레이 해결

기존 구조는 StateTask에서 입력을 판단하고, 입력에 의해 패널을 다시 그려야 한다고 판단되었을 때 디스플레이 패널에게 요청하는 구조였다. 문제는 lcd 모듈에 그리는데 시간이 약간 필요하다는 것이다. lcd 모듈에 그리는 동안 새로운 요청이 계속 들어오면 요청을 제때 처리하지 못하고 늦어지게 된다. 그래서, 디스플레이 태스크도 주기적으로 출력을 하도록 구조를 수정했다. 대신 StateTask에서는 파라미터를 업데이트 하거나 UI 상태를 전이한 후 디스플레이 태스크에게 렌더링해야할 정보를 큐에 전송한다. 이 때 큐는 메일박스로, 길이가 1이며 덮어쓰기가 된다. 디스플레이 태스크에서는 마지막으로 덮어씌워진 정보를 읽고 LCD모듈을 그리고 led의 출력 상태를 바꾼다. 이렇게 하니 출력에 걸리는 딜레이가 사라졌다.

# 뮤텍스로 i2c 동시 접근 문제 해결

LED 출력을 구현하면서 DisplayTask와 InputTask가 동시에 i2c에 접근하는 상황이 발생한다. 특히 DisplayTask가 i2c 처리를 하는 중에 InputTask가 i2c를 쓰려고 하면, 이미 누군가 i2c를 쓰는 중이므로 오류가 발생한다. 이를 해결하기 위해 뮤텍스를 적용하여, i2c를 쓰는 상황에 뮤텍스를 획득하고 반환하면서 한 번에 한 태스크만 i2c를 쓰도록 제약을 걸었다.

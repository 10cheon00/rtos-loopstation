# 노브 인디케이터 렌더링

이전에 제대로 구현하지 않았던 노브 인디케이터를 제대로 렌더링 하기 위해 AI에게 물어보니 이미 있는 알고리즘을 소개해주었다. Bresenham 알고리즘인데, 원리는 잘 모르겠다. 대신 반복문 조금만 돌리면 시작 지점에서 목표 지점까지 x좌표를 이동시키거나 y좌표를 이동시켜서 직선을 그려낸다. 왜 그런지는 이해해야할 필요가 없다고 생각했다. 이게 중요한게 아니니깐..

# FX 패널 구현을 위한 설계 변경

FX 마다 파라미터 수가 다르므로 이를 기존 설계대로 구현한다면 FX 수 * 파라미터 수만큼의 패널 파일이 작성되어야 한다. 그 파일들의 내용은 대동소이하므로, 패널 파일을 수십개 만드는 것보다 설정 파일 하나를 관리하는 편이 훨씬 낫다. 
현재 설계는 패널 하나에 파라미터 4개를 할당하는 설정을 기반으로 렌더링 함수를 호출하게 되는데, 해당 설정이 패널 외부에 있기 때문에 패널 내에서 보여주고 싶은 파라미터가 달라질 경우 이를 반영할 수 없다. 따라서 패널이 보여주고 싶은 파라미터를 패널이 직접 선택할 수 있도록 패널 내부에 파라미터 설정을 보관하도록 수정했다. 그렇게 한다면 이벤트가 발생할 때 트랜지션 대신 보여주고 싶은 파라미터를 변경하는 등의 작업이 가능해진다. 
기존에는 UI_ACTION 이벤트가 발생하면 상태 머신이 상태 내부에 정의된 트랜지션 테이블을 보고 다음 상태를 골라 전이했다면, 수정한 설계에서는 UI_ACTION 이벤트가 발생할 때 패널이 가진 OnEvent함수를 호출한 후 상태 전이를 결정하도록 한다. 

여기까진 어느정도 완료했는데, 아직 FX 설정 패널을 만들지 않았다. 그리고 문제점이 있는데 렌더러에서 상단 화살표를 정적으로 출력하고 있다는 점이다. 이 정보를 렌더러에게 알려주어야 한다. 그리고 현재도 하드코딩 되어 있는 상태다. 이 부분은 메일박스에 멤버를 추가하면 해결될것 같다.


# 엔코더 ID 사용

엔코더는 딱 4개만 쓸거라서 하드코딩을 해도 된다고 생각한다. ID도 딱 4개만 만들고 버튼 입력을 처리할 때 4개만 하드코딩해서 처리하도록 했지만 이것도 나중에 리팩토링하게 될 것 같다.

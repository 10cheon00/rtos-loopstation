# 문제점

파라미터를 리팩토링하면서 저장소를 두 개로 나누었고 ID 형식을 하나의 enum에 모두 저장하지 않고 Fx 파라미터를 구조체 멤버화 시켰다. 이 변화가 상태 관리 태스크와 디스플레이 태스크에는 반영되지 않았다. 특히 Ui 상태 머신의 각 상태는 Page 형태로 파라미터나 메뉴를 슬롯에 담아 보관하고 있는데, 이 때 보관하는 파라미터는 시스템 파라미터 뿐이다. Ui 상태 머신이 Fx파라미터도 보관할 수 있도록 개선해야한다. 

## AI가 개선이 필요하다고 판단한 처리 흐름

1. Page의 파라미터 식별(ParameterSlot에 ParameterModel::Id 저장)

  파라미터 슬롯은 Ui 상태가 갖는데 여기에 사용되는 ID가 시스템 파라미터만 다루는 ParameterModel::Id임. 시스템 파라미터와 Fx 파라미터를 모두 아우르는 고유 Id가 필요함.

  그리고 Ui 상태가 이 Id를 가질 수 있도록 구조를 수정해야함.

2. 엔코더에 의한 수정(GetParameterFromCurrentPageAt()에서 시스템 저장소 조회)

  고유한 ID 값과 매핑된 저장소에 접근하여 파라미터를 가져올 수 있어야 함. ID로부터 저장소를 구분하고, 그 저장소에서 값을 가져오는 구조를 구현해야함.

3. 출력용 값 복사(CopyPanelSlotsToPanelRenderPayload()에서 시스템 저장소 조회)

  디스플레이 태스크에서는 상태 관리 태스크 내부 구조와 독립적으로 주어진 파라미터 또는 메뉴를 어떤 위젯으로 출력시킬지만 고민하면 된다. 시스템 파라미터와 Fx 파라미터 모두 공통 ParameterValue 객체들을 쓰고 있으므로, 객체가 C,C++경계를 통과하면서 이를 구분할 수 있는 메시지 구조를 정의하면 된다.

## 실제 개선 방향

### Ui 상태 및 페이지 구조 개선

Page에 ParameterId만 저장하던 문제 및 Ui상태가 고정된 페이지들을 갖는 문제를 해결하기 위해 Ui상태에 결합되어 있던 페이지슬롯들을 분리했다. 분리한 페이지 슬롯을 페이지 그룹으로 변경하고, 페이지 그룹에는 기존 Page가 담기도록 수정했다. Page에는 시스템 파라미터뿐만 아니라 Fx 파라미터도 있어야 하므로 당장은 파라미터 ID들을 각각 구조체에 담은 후 variant로 함께 담을 수 있도록 변경했다. 각 상태를 나타내는 클래스를 정의하고, 인스턴스를 생성할 때 기본 PageGroup을 주입한다. 아직 페이지 그룹 교체 기능을 개발하지 않았지만 런타임에 교체하는 기능을 개발할 예정이다.

### Fx 파라미터 저장소 개선

한 Fx에 속한 파라미터들을 구조체로만 저장하니 단일 파라미터를 가져와야할 때 구조 상 한계가 나타났다. 오디오 태스크에서는 이 저장소에서 값을 가져올 때 구조체로 가져오고 있었기 때문에, 시스템 파라미터와 동일한 구조로 저장소를 개선하고 오디오 태스크에서 접근할 때는 Dto 구조체로 값을 반환하도록 했다. 상태 관리 태스크에서는 Fx 파라미터 수정 시 Ui 상태가 가진 페이지 그룹을 조회하여 수정해야할 파라미터의 ID를 얻고 그 ID로 저장소에 접근해 값을 수정한다.
